# 战术层设计：编队机动 + 路口合围打击

> 目标：在现有「无人机侦查 → 无人车打击」闭环之上，加一层**战术决策**：
> 车辆不再「发现一个派一辆」，而是**成队推进、分批接敌、按阵位合围、到齐才开火**。
> 本层为全新目录 `WorkPlace/tactics/`，**不改动** `missions/full_mission.py` 及其依赖。

---

## 0. 范围与非目标

**本版做**

| 编号 | 内容 |
| --- | --- |
| P0 | 战术层骨架 + `strike_plan.json` + 区域参数化（防串场景） |
| P1 | 滚动重分配、编队跟随、前沿待机 |
| P2 | 路口分类撒点 + 合围阵位 + 「到齐才开火」 |
| P3 | 指标统计与演示开关（A/B 对照） |

**本版不做**

- 移动敌人（敌人不逃跑、不换路口）——列入后续工作；
- 自由空间等角环阵（我们的车只能走道路）；
- MARL / 强化学习类分配（3 车规模下穷举即最优）；
- ORCA 级别避碰（现有让行/超车够用）。

## 1. 场景与区域（含「防串场景」约束）

### 1.1 使用区域

沿用 `practice1`，只取**路口密集区**，初值：

```
--zone "-772,-1006,128,-306"       # x0,y0,x1,y1，900×700 m，路口 143 个（实测最密窗口）
```

> 已用 `tools/pick_junction_area.py` 实测校准：骨架图共 732 个路口像素，900×700 窗口里
> 最密一块 = 143 个路口，即 `--zone "-772,-1006,128,-306"`（像素 x[1323,2223] y[1631,2331]）。
> 像素→世界坐标的映射存放在 `config/roadnet_meta.json`（`world = px*scale + offset`）。

### 1.2 三条防串场景的硬规则（针对此前「测试图逻辑混进半图」事故）

1. **区域只有一个来源**：`tactics/zones.py` 里定义 `Zone(rect, name)`，所有脚本**必须显式传** `--zone`，
   **不提供默认值、不提供 `auto` 兜底**。缺参数直接报错退出，不许猜。
2. **撒点、巡逻、小地图共用同一个 `Zone` 对象**：撒点器拿到 rect 后先断言「每个点都在 rect 内」，
   不满足就抛异常，不静默修正。
3. **旧入口不受影响**：`full_mission.py` 继续用它自己的 `--area`；`tactics/` 的入口只读 `--zone`。
   两套参数名不同、互不读取，杜绝「一个脚本顺手改了另一个的常量」。

## 2. 架构

```
侦查（沿用 existing）               战术层（新增）                    执行（沿用 existing）
UAV 牛耕 → detected.json  ──►  tactics/targets.py  目标事件+路口分类
UAV 覆盖栅格 ─────────────►  tactics/coverage.py 未覆盖前沿
                                     │
                                     ├─ tactics/slots.py    阵位生成（分支识别/围三缺一/路网吸附）
                                     ├─ tactics/assign.py   滚动重分配（瓶颈指派+承诺分级+防抖）
                                     └─ tactics/formation.py 编队（领航-跟随、纵队/楔形）
                                     │
                                     ▼
                            strike_plan.json（原子写 + mtime 热加载）
                                     │
                          missions/tactics_mission.py（新入口）
                                     │
                                     ▼
                    UgvAgent（现有能力：A*、让行、超车、开火）
```

**关键点**：战术层不直接控车，只产出「谁、去哪个点、什么时候出发、什么条件开火」；
执行仍由现有 `UgvAgent` 完成。这样战术层可以脱离仿真单测。

## 3. 数据契约 `strike_plan.json`

沿用现有 `goals.json` 的「原子写 + mtime 热加载」模式，新增一个文件：

```json
{
  "plan_id": 17,
  "t_plan": 128.4,
  "line": {
    "leader": "UGV1",
    "members": ["UGV2", "UGV3"],
    "formation": "column",
    "anchor": [812.0, 700.0]
  },
  "groups": [
    {
      "target_id": "E3",
      "kind": "junction",
      "junction_degree": 4,
      "gap_branch": "N",
      "slots": [
        {"vid": "UGV1", "branch": "E", "pos": [905.0, 700.0], "hold": [860.0, 700.0], "eta": 21.3},
        {"vid": "UGV2", "branch": "S", "pos": [812.0, 780.0], "hold": [812.0, 740.0], "eta": 24.0},
        {"vid": "UGV3", "branch": "W", "pos": [720.0, 700.0], "hold": [755.0, 700.0], "eta": 19.8}
      ],
      "t_star": 24.0,
      "go_at": 21.0,
      "fire_rule": "all_arrived_minus_gap",
      "state": "assault"
    }
  ],
  "idle": [
    {"vid": "UGV3", "frontier": [640.0, 520.0], "reason": "uncovered_frontier"}
  ],
  "commitment": {"UGV1": "L1", "UGV2": "L1", "UGV3": "L0"}
}
```

字段含义：

| 字段 | 说明 |
| --- | --- |
| `line` | 当前编队；`formation` ∈ `none/column/wedge`，`anchor` 为领航车目标点 |
| `slots[].hold` | 集结点（在阵位上游 30~50 m，视野外），先到点等 GO |
| `t_star` | 全部到位的统一时刻（瓶颈指派求得） |
| `go_at` | 广播 GO 的时刻 = `t_star − t_assault` |
| `fire_rule` | `all_arrived_minus_gap`：就位数 ≥ 分支数−1 且分布 ≥2 个分支才开火 |
| `idle[]` | 空闲车的待机前沿点（永远不选区域边界附近的点） |
| `commitment` | `L0` 空闲可改派 / `L1` 已出发，改进>20%才改派 / `L2` 已到集结点，锁定 |

## 4. 三个常态行为

### 4.1 滚动重分配（解决「车在远处、近处车闲着」）

- **触发**：新敌人出现 / 敌人被消灭 / 车辆受阻 / 每 5 s 定时；
- **求解**：3 车 × M 阵位，分组枚举 + **瓶颈指派**（最小化最晚到达），3×3 时直接枚举 6 种排列；
- **代价**：`J = 0.5·max(ETA) + 0.3·(1−覆盖率) + 0.15·威胁·等待时长 + 0.05·改派次数`；
- **防抖**：新方案必须优于旧方案 20% 才下发；单目标改派上限 2 次。

### 4.2 编队跟随（解决「三车被拉得很散」）

- 有任务的车出发时，其余车**先编队跟到距目标 ~200 m 的集结点**，而不是原地不动；
- 队形按路宽自适应：可通行宽度 ≥ 2×车宽+余量 → `wedge`，否则 `column`；
- 切换不停车，偏移量按 τ=0.6 s 一阶滤波过渡；
- 新任务下达时，从编队中**直接分裂**（split），不必回队集合。

### 4.3 前沿待机（解决「闲置车没事干」）

- 无人机发布覆盖栅格（已有 200 m 记账，可直接复用）；
- 取「已覆盖 / 未覆盖」交界带上的路网点作为候选；
- **排除规则**：距任务区边界 < 100 m 的候选点直接丢弃（避免车往地图边缘跑）；
- 每辆空闲车选「最近的、未被其他车占用的」前沿点，带 50 m 滞回防抖。

## 5. 路口合围打击

### 5.1 敌人分类（撒点规则改动）

| 类型 | 规则 | 比例 | 打击方式 |
| --- | --- | --- | --- |
| `road` | 距最近路口 > 60 m 的路段上 | ~70% | 单车到点即开火 |
| `junction` | 路口中心 15 m 内，且路口度数 ≥3 | ~30% | **合围 + 到齐才开火** |

分类由撒点工具在生成时写入 `targets.json` 的自定义字段（`kind`、`junction_degree`），
运行时无需再算。

### 5.2 阵位生成

1. 以敌人为圆心取 r=40 m，把邻域内的骨架边按方向角聚类（间隔阈 35°）得到 m 个分支；
2. `m ≥ 3`：封 m−1 个分支，缺口取「最远离我方来向」的分支；
   `m = 2`：首尾夹击；
   `m = 1`：退化为单车抵近；
3. 每个分支上取「距敌人 25~35 m」的路网点作为封锁位，再向本车方向退 30~50 m 设集结点；
4. 阵位必须通过 A* 可达校验，不可达换下一个分支；全部不可达则降级为 `m−1` 组合围。

### 5.3 开火条件

```
可开火 = 就位车辆数 ≥ (m − 1)  且  就位车辆分布在 ≥ 2 个不同分支  且  全部在射程内
```

- 未满足时车辆在封锁位**停车待命**，不先开火（避免单车暴露）；
- 满足后**同时开火**；击杀后按普通目标回收（就地转空闲）。

### 5.4 降级链

`3 车合围 → 2 车夹击 → 1 车抵近`，每次降级写一条事件，便于统计「本局降级次数」。

## 6. 状态机（单目标）

```
S0 发现 → S1 分类 → S2 阵位生成 → S3 指派 → S4 集结点待命
   → S5 同步突击（GO） → S6 合围达成/开火 → S7 目标消灭 → 回收
异常回边：
   目标丢失  → S0（重新侦查确认）
   阵位不可达 → S2（换分支）
   车辆受阻  → S3（局部重分配）
   长时间未达成 → S4（强制 GO 或降级）
```

## 8. 里程碑与验收

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| P0 | `zones.py` / `plan_io.py` / `pick_junction_area.py` | 缺 `--zone` 报错；撒点全部落在 zone 内；计划文件能被小地图画出 |

## 9. 参数默认值

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 重规划周期 | 5 s | 事件触发优先 |
| 改派改进阈值 | 20% | 防抖 |
| 集结点退距 | 30~50 m | 视野外 |
| 同步容差 δ | 2.0 s | 到齐判定的时间窗 |
| 缺口分支选择 | 最远离我方来向 | 可换「通向开阔地」评分 |
| 前沿点离边界 | ≥100 m | 避免贴地图边 |
| 合围半径 | 25~35 m | 阵位到敌人距离 |

## 10. 风险与降级

| 风险 | 应对 |
| --- | --- |
| 阵位落不到路网 | A* 可达校验 + 换分支 |
| 三车同时挤路口堵死 | 集结点错峰出发 + 现有让行/超车兜底 |
| 重分配抖动 | 改进阈值 + 改派次数上限 + 承诺分级 |
| 合围永远等不齐 | 超时（`t_star + 10 s`）触发降级 |
| 新层拖慢主循环 | 决策固定 0.1 s 节拍，与渲染解耦 |
