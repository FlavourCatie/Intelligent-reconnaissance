# 飞控调不通 —— 根因、证据与修复

- 定位日期：2026-11-02
- 定位人：littleZ05
- 环境：Windows 11 / i5-12500H / RTX 2050 / conda `kyxz` (Python 3.6.13)
- 涉及文件：课程包 `simu_driver_windows`（飞控主控 + 驱动 + ArduPilot SITL）

---

## 0. 一句话结论

**飞控没坏，SDK 也没坏 —— 是工作区路径里的空格把飞控驱动启动 SITL 的命令行劈开了。**

`driver.exe` 拉起 ArduPilot SITL 时把命令行拼成**一个字符串**，
`--defaults <路径>` 没加引号；我们的工作区叫 `D:\Intelligent Unmanned Systems`（有空格），
于是参数被切成两半，后面的 `--serial0 udpclient:127.0.0.1:<端口>` 整段丢失，
SITL 退回默认的 **TCP 5760**，飞控驱动再也收不到 MAVLink 心跳：

```
[__init__.py.listener] WARNING Link timeout, no heartbeat in last 5 seconds   ×3
dronekit.APIException: No heartbeat in 180 seconds, aborting.
[basesimuobject.py.connect] ERROR UAV#0/1/2: Connect Timeout!
```

没有动力学实例 → `control_kinetic_simply()` / `_global()` 照样返回 200，
但**飞机零位移**，`get_kinetic_data()` 恒为 None，M10 只剩自由落体。
这正是我们 10 月 27 日看到的那一整套"灵异现象"。

**修复：给课程环境做一个不含空格的入口（目录联接），从那里启动 `start.bat`。**
已实测：改走 `C:\kyxz\...` 之后，SITL 立刻回心跳（1.1 s 内）。

## 2. 链路长什么样

```
  SDK(算法)                CarlaUE4(场景/物理)              subject4.exe(撒点)
     │  TCP 2000                    ▲   │ 4443 上报
     ▼                              │   ▼
  ┌────────────────────────────────────────────────┐
  │              main-release.exe（飞控主控）        │   ← "SUBCONTROL" 横幅、心跳
  │   TCP 4443 (UE4)   TCP 4444 (驱动登录)          │
  └────────────────────────────────────────────────┘
                     ▲ 4444 登录 / UDP 4445 消息
                     │
  ┌────────────────────────────────────────────────┐
  │                 driver.exe（飞控驱动）           │   ← dronekit
  │  每架飞机起一个 ArduPilot SITL，用 UDP 收 MAVLink │
  └────────────────────────────────────────────────┘
                     │ Popen("model ... --serial0 udpclient:127.0.0.1:PORT")
                     ▼
  ┌────────────────────────────────────────────────┐
  │  model = ArduPilot SITL (Cygwin, ArduCopter)     │
  └────────────────────────────────────────────────┘
```

关键在最后一段：**飞控驱动是靠 UDP 收 SITL 的 MAVLink 心跳来"认领"这架飞机的。**
心跳不到，飞机就等于不存在——但上层接口不会报错，只会静默地什么都不做。

课程包里 Linux 版留档的启动命令（`bin/driver/bin/fixed_wing_linux/t.txt`）能看清协议：

```
model -S --model plane --home 32.0,118.0,0.0,0.0 \
      --defaults .../default.parm \
      --base-port 28477 --serial0 udpclient:127.0.0.1:28477 -I0 --sysid 1
```

`--serial0 udpclient:127.0.0.1:<base-port>` = SITL 把 MAVLink **发到**飞控驱动监听的端口。
Windows 版一模一样，只是换成 `quadrotor_windows\model` + `--model quadrotor`。

## 3. 证据

### 证据 1：SITL 本体在 Windows 上完全正常

用**参数列表**（Windows 会正确加引号）拉起它：

```
 判定      : PASS 有 MAVLink 心跳
 收包      : 23 个（其中 HEARTBEAT 14 个）
 首个心跳  : 启动后 1.1 s
 SITL 输出 : UDP connection 127.0.0.1:28400
             Loaded defaults from ...\default.parm
```

SITL 起来、读到参数、主动往驱动的端口发心跳 —— 一切都对。
**所以"交付的 SDK / 驱动打包不完整"这个判断是错的。**

### 证据 2：按驱动的拼法（整串、不加引号）+ 带空格路径 → 必然失败

同一台机器、同一个二进制，只把 `--defaults` 的路径换成带空格的工作区：

```
 判定      : FAIL 收不到心跳
 收包      : 0 个
 SITL 输出 : bind port 5760 for 0
             Serial port 0 on TCP port 5760
             Waiting for connection ....        ← 等一个永远不会来的连接
```

对比一眼就能看出：`--serial0 udpclient:...` 被吞掉了，SITL 退回默认 TCP 5760，
`Loaded defaults` 也没了。这条输出与飞控驱动日志里的 `Connect Timeout!` 严丝合缝。

两条证据合起来就是排除法：
**SITL 好 + 心跳机制好 + 只有路径带空格时断 = 路径是变量。**

这个实验已经做成工具，谁都能复跑（见第 5 节）：

```powershell
python WorkPlace\tools\sitl_probe.py
```

### 证据 3：课程作者的环境是无空格路径

课程包自带的历史日志里，作者机器上的路径是：

```
D:\Englishpathfolder\kyxz\environment\simu_driver_windows\...
```

**没有空格**，所以他那边永远踩不到这个坑；我们的 `D:\Intelligent Unmanned Systems` 才会。
（同一份课程包的 `start.bat` 也因为同样的空格问题被我们改过 —— 见
`环境配置踩坑记录.md` 坑 5。这是同一个病根的第二处发作。）

## 4. 为什么之前会误判成"SDK 空壳"

三个"看起来像 SDK 坏了"的坑，其实各有出处：

| 观察 | 真相 |
|---|---|
| `launch_kinetic()` 18 组全返回 `None` | **它在 V1.4 里就被删了**（版本记录第 9 行），SDK 里只剩一个 `return None` 的空壳。反编译 `SwarmAENode.pyc` 确认：`launch_kinetic` 的字节码就是 `LOAD_CONST None; RETURN_VALUE`。**它从来不是启动动力学的按钮**，继续枚举参数是死路 |
| `control_kinetic_simply()` 返回 200 但不动 | 它的实现是 `self.__actor.set_proto_target_and_speed(carla.Location(x,y,z), v)` —— 目标点发给 UE4 里的飞机 actor，由它转给飞控主控。**驱动侧没有实例，指令就落空**，但 `set_proto_target_and_speed` 自己没抛异常，所以返回 SUCCESS |
| `get_kinetic_data()` 恒 None | 同 `launch_kinetic`，V1.4 已删。要读飞行数据请用 `get_kinetic_data_simply()` / `get_location()`（它们读 actor 的 transform，不受飞控影响） |

顺带纠正《SDK 接口说明 V1.4》与本 SDK 的一处口径差异：
文档写 `control_kinetic_simply` 的 `z` 是 **D（地心向下）**，
而 SDK 的 docstring 写的是 **U（海拔向上）**，实现直接把 `z` 塞进 `carla.Location`。
以 **U（向上）** 为准更安全 —— 但请在飞控通了之后用小步长实测确认。

## 5. 怎么修（三种，任选一种；推荐 A）

### A. 做无空格目录联接（推荐，零拷贝、可回退）

```powershell
python WorkPlace\tools\sim_link.py --create
```

它做的事就一句：

```cmd
mklink /J C:\kyxz "D:\Intelligent Unmanned Systems\environment_forclass"
```

- **不复制数据**（10 GB 一个字节都不动）、不需要管理员、即时生效；
- 之后**从联接路径启动飞控**：

```powershell
C:\kyxz\environment\simu_driver_windows\start.bat     # 选 2（四旋翼）
```

- `driver.exe` 的 `sys.executable` 于是是 `C:\kyxz\...`，一路无空格；
- CarlaUE4 / subject4.exe **不用动**，原路径照旧；
- 不想要了：`python WorkPlace\tools\sim_link.py --remove`（只删联接，不删数据）。

### B. 真把课程环境搬到无空格路径

```powershell
# 关掉仿真器和驱动后
move "D:\Intelligent Unmanned Systems\environment_forclass" C:\kyxz_src\environment_forclass
```

然后在 `WorkPlace` 下用环境变量指过去（避免工具到处找）：

```powershell
$env:SWARMAE_ENV_ROOT = "C:\kyxz_src\environment_forclass\environment"
```

### C. 工作区改名（最彻底，但会牵动所有文档/快捷方式）

把 `D:\Intelligent Unmanned Systems` 改成 `D:\IntelligentUnmannedSystems` 之类。
不推荐现在做——路径被大量文档引用，收益与 A 相同。

## 7. 剩下的注意事项

1. **启动顺序**：CarlaUE4 → start.bat → subject4.exe。驱动比世界先起，绑不上飞机。
2. **`Type` 必须与机型一致**：`start.bat` 选 2 → `config.yaml` 里 `Type: quadrotor`。
   现在是 quadrotor，`env_guard.py` 会帮你盯。
3. **端口冲突**：2000 上出现两个监听者 = 两个 CarlaUE4，脚本会连错世界。
   `python WorkPlace\tools\kill_all.py` 一键清场。
4. **无人机 actor 的物理**：飞控通了以后，M10 的位姿由飞控/SITL 接管，
   之前"关不掉物理、清不掉速度"的绕法（`set_simulate_physics(False)` 会触发 UE4 断言）
   **应当全部撤掉** —— 那些是"没有动力学时"的应急手段，留着反而打架。
5. 飞控通了以后再考虑：`--uav-mode kinetic` 下把 `uav_runner` 的运动学模式作为 fallback，
   而不是默认。切换前先跑 ② ③ 两遍确认。
