# 环境防污染规范

- 建立日期：2026-11-02
- 适用：所有要跑 `WorkPlace` 代码的人
- 配套工具：`WorkPlace/tools/env_guard.py`

---

## 1. 我们说的"环境污染"到底指什么

这套课的运行环境有三层，**每一层都被踩过**：

| 层 | 长什么样 | 怎么被污染 | 后果 |
|---|---|---|---|
| **Python 依赖** | conda 环境 `kyxz`（3.6.13），直接装全局，不是 venv | 任何人 `pip install -U numpy` / 装个新轮子 | SDK 的 `cp36` 扩展加载失败，或 numpy ABI 不兼容，报一堆看不懂的错 |
| **课程 SDK** | `easy_install` 装进 `kyxz` 的两个 `.egg` | 重装/换版本/`pip install -e` | `import swarmae` 行为改变，`control_kinetic_*` 静默失效 |
| **课程包二进制** | 10 GB 的 `environment_forclass`（不进仓库） | 手改 `config.yaml`、`start.bat`、换 `subject4.exe` | 飞控 `Type` 不对、场景对不上、start.bat 编码被改坏 |

再加上第四类"假污染"：**运行时产物写进仓库目录**（`skeletonized_image.tga` 66 MB、
`*.log`、`track_log_*.csv`、`figs/uav_view/`），一提交就把 diff 冲烂。
这一类已经由 `.gitignore` 兜住，但**别指望 `.gitignore` 帮你收拾磁盘**。

## 2. 三道闸门

### 闸门 1：一条命令体检（每次开工前 10 秒）

```powershell
conda activate kyxz
python WorkPlace\tools\env_guard.py
```

看 `小计` 那一行：**FAIL 必须清零**，WARN 看是否与你有关。它会检查：

- Python 必须是 3.6 / 64 位（SDK 是 `cp36-win_amd64`，换版本必炸）；
- 关键依赖版本是否还对得上基线（`numpy 1.19.5` 等 8 个）；
- `swarmae` / `swarmae_lib` 能否导入、关键接口在不在；
- 课程包文件 + SITL 二进制在不在、`config.yaml` 的 `Type` 对不对；
- 路径里有没有空格（飞控致命，见 `飞控调通_根因与修复.md`）；
- 端口 2000/4443/4444/3301/3302、进程与启动顺序。

### 闸门 2：指纹 + 漂移比对（抓"谁动了环境"）

```powershell
# 环境确认干净时，存一份基线（建议提交进仓库）
python WorkPlace\tools\env_guard.py --snapshot WorkPlace\env\env_snapshot.json

# 以后任何时候：跟基线比，列出每一处变化
python WorkPlace\tools\env_guard.py --diff
```

输出形如：

```
  packages.numpy                                1.19.5  ->  1.24.0
  files.simu_driver_windows/bin/driver/config.yaml  ...  ->  ...
```

**只要不是你自己改的，就按"被污染"处理**：不要试图理解它为什么坏，直接按第 4 节还原。

### 闸门 3：不往共享环境里装东西

- 需要新库？先问自己能不能用标准库（本项目刻意只用标准库 + 课程 SDK）。
- 真的必须加：把**精确版本**写进 `WorkPlace/env/requirements.txt`，
  在组内同步，然后 `pip install -r`，**不要 `--upgrade` 已存在的包**。
- **禁止**在 `kyxz` 里装与课程无关的工具（分析脚本、爬虫、jupyter 插件、decompiler……）。
  要装就新建一个独立环境：`conda create -n tools python=3.11`。

## 3. 硬规则清单

| ✅ 做 | ❌ 别做 |
|---|---|
| `conda activate kyxz` 后再跑 | 用系统 Python 3.14 / 其他环境跑（`env_guard` 会 FAIL） |
| 改动课程包前先备份，改完记进 `环境配置踩坑记录.md` | 直接手改 `bin/driver/config.yaml`（用 `start.bat` 选机型） |
| 新依赖写进 `env/requirements.txt` + 改基线快照 | `pip install -U` 已在的包 |
| 运行时产物写到 `figs/`、临时文件用 `temp/`（已 ignore） | 往仓库根写 `.tga`、`.log`、`.csv` |
| 课程包放在**无空格**路径（或走 `C:\kyxz` 联接） | 把 10 GB 课程包拷进仓库 / 提交 `.exe` |
| 一键清场 `tools\kill_all.py` | 同时开两个 CarlaUE4（2000 端口打架） |

## 4. 环境被污染后：还原流程（15 分钟）

```powershell
# 0) 先看差在哪，留证据
python WorkPlace\tools\env_guard.py --diff > env_drift.txt

# 1) 把版本拉回基线（按 env/requirements.txt，不升级别的）
conda activate kyxz
python -m pip install -r WorkPlace\env\requirements.txt

# 2) 如果 SDK 被动过：按 env/README.md 重装两个 egg
python -m pip install setuptools==44.1.0
cd "C:\kyxz\environment\sdk\windows"     # 或你本机路径
conda run -n kyxz easy_install -i https://pypi.tuna.tsinghua.edu.cn/simple swarmae_lib-0.1.1-py3.6-win-amd64.egg
conda run -n kyxz easy_install -i https://pypi.tuna.tsinghua.edu.cn/simple swarmae-1.1-py3.6-win-amd64.egg

# 3) 复核
python WorkPlace\tools\env_guard.py
python WorkPlace\tools\env_guard.py --diff      # 应无输出
```

如果拉不回来（Python 版本都变了），就**重建整个环境**：
`WorkPlace/env/README.md` 里有从零开始的完整命令（含国内镜像、坑位说明）。

## 5. 为什么不在仓库里放一个 `environment.yml`

试过，但：

1. `.egg`（`cp36` 二进制）不是 pip 包，`conda env export` 表达不了；
2. 环境里有一半东西来自课程包（`easy_install` 装的），另一半是 pip/conda 的，
   混在一份文件里会产生"看起来能一键复现、实际必然失败"的假承诺。

所以现在的做法是**两个文件分工**：

- `env/requirements.txt` —— pip 层，精确版本，可一键装；
- `env/README.md` —— 人和课程包才有的东西（conda 建环境 + `easy_install` 两个 egg + 镜像/网络坑）。

## 6. 与飞控的关系（为什么这条规范不只是"洁癖"）

本轮排查飞控，一半时间花在**排除环境因素**上：SDK 空壳、驱动打包、物理开关……
最后定位到的根因是"路径带空格"这种环境问题，而它**不会报错、只会静默失效**。

`env_guard.py` 把这类"静默失效"变成一张表：
Python 版本、包版本、路径空格、SITL 在不在、端口在不在，一眼看完。
以后谁再遇到"飞机不动 / 车不动 / 连不上"，先跑它，再谈代码。
