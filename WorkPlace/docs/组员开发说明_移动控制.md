## 3. 你的核心任务：设计"怎么移动"

对每台平台，你的输入是**当前状态**，输出是**控制量**（车）或**目标点**（机）。

### 3.1 输入：读状态

```python
snap = fleet.snapshot()          # {name: Pose}
p = snap["UGV1"]
p.x, p.y, p.z                    # 位置（米）
p.yaw                            # 朝向（弧度）
p.v                              # 速度（m/s）
p.moving                         # 是否在动
```

或逐台精细读取：

```python
v = fleet.vehicle("UGV1")
st = v.get_state()               # st.pose_.x_ / .y_ / .theta_ / .z_ ，st.v_
```

### 3.2 输出 A：无人车（闭环，给油门/转向/刹车）

```python
v.apply_control(steer, throttle, brake, hand_brake)
```

| 参数 | 范围 | 说明 |
|---|---|---|
| `steer` | `[-1, 1]` | 转向。**这是第一个参数，别看错顺序** |
| `throttle` | `[-1, 1]` | 正=前进，负=倒车 |
| `brake` | `[0, 1]` | 刹车 |
| `hand_brake` | `True/False` | 手刹 |

### 3.3 输出 B：无人机（开环，给目标点 + 地速）

```python
v.target_point_control(x, y, z, v)      # 目标点(米) + 地速(m/s)
```

无人机**没有**"给油门/转向"的接口，底层自己飞。所以你的算法重点是：
**下一个航点选哪里、什么时候算到达**，不要试图写速度闭环控制器（SDK 不给）。

### 3.4 两条路，任选

**路线 1（最快见效）：直接用现成的**
`core/fleet.py` 里已经实现了 A\* 走道路 + Stanley 横向 + PID 纵向 + 无人机航点跟随：

```python
fleet.set_targets({"UGV1": (1200, -400), "UAV1": (1400, -500)})
fleet.plan(scene, img_skl)        # 车：A* 走道路；机：直线
while True:
    fleet.step(0.05)              # 内部算控制量并下发
    time.sleep(0.05)
```

适合：先把流程跑通、调速度/间距/增益。

**路线 2（自己写算法）：只用接口，中间你自己算**

```python
while True:
    snap = fleet.snapshot()
    for name in ["UGV1", "UGV2", "UGV3"]:
        p = snap[name]
        # ↓↓↓ 这里换成你的算法 ↓↓↓
        goal = GOALS[name]
        dx, dy = goal[0] - p.x, goal[1] - p.y
        dist = (dx*dx + dy*dy) ** 0.5
        heading_err = np.arctan2(dy, dx) - p.yaw     # 目标方位与当前朝向之差
        steer = np.clip(heading_err * 1.5, -1, 1)
        throttle = 0.6 if dist > 10 else 0.0
        brake = 1.0 if dist <= 10 else 0.0
        # ↑↑↑ 这里换成你的算法 ↑↑↑
        fleet.vehicle(name).apply_control(steer, throttle, brake, False)
    time.sleep(0.05)
```

适合：做编队、合围、覆盖搜索、中继这些**任务级**算法。

> 我建议**初期用路线 1 打通，再逐段替换成路线 2**。

## 4. 目标点接口（**这一节最重要**）

你要让"车/机去哪"这件事**被我这边看到**，唯一的办法是写进这个文件：

### 4.1 文件位置与格式

`WorkPlace/config/goals.json`

```json
{
    "UGV1": [1200, -400],
    "UAV1": {"x": 1400, "y": -500}
}
```

* 键 = 平台名（**只能是** `UGV1` `UGV2` `UGV3` `UAV1` `UAV2` `UAV3`）
* 值 = `[x, y]` 或 `{"x":…, "y":…}`，单位**米**
* **保存即生效**：我这边每帧查文件修改时间，改了就更新星标，不用重启
* **没写到的平台**：我这边会自动按"离它最近的敌人"画一个空心星标
* 想清空全部人工目标：加 `"__清空__": true`
* 以 `__` 开头的键会被忽略（可以用作注释，参考文件里的 `__说明__`）

### 4.2 为什么会自动显示

我这边每台平台画两个东西：

| 图形 | 含义 |
|---|---|
| **实心星标** + 虚线 | 来自 `goals.json`（人工指定） |
| **空心星标** + 虚线 | 没指定，自动取"最近敌人" |
| HUD 里的 `[指定]` / `[默认]` | 对应上面两种来源 |

**所以你只要把目标写进这个文件，我这边立刻就能看到——不用告诉我、不用重启。**

### 4.3 在你脚本里怎么写这个文件

```python
import json, os, tempfile

GOALS_PATH = r"<你的路径>\WorkPlace\config\goals.json"

def write_goals(mapping):
    """mapping: {"UGV1": (1200, -400), ...}"""
    data = {k: [float(v[0]), float(v[1])] for k, v in mapping.items()}
    # 先写临时文件再替换，避免我这边读到"写了一半"的 json
    d = os.path.dirname(GOALS_PATH)
    fd, tmp = tempfile.mkstemp(dir=d, suffix=".json")
    with os.fdopen(fd, "w", encoding="utf-8") as f:
        json.dump(data, f, indent=4, ensure_ascii=False)
    os.replace(tmp, GOALS_PATH)
```

> ⚠️ **一定要用"先写临时文件再 `os.replace`"的方式**。直接 `open(...,'w')` 写的话，
> 我这边可能正好读到只写了一半的文件，会解析失败（虽然有 try/except 兜着，但会漏一帧）。

### 4.4 演示中动态改目标

这是这个接口最大的用处：**跑的过程中你重新分配目标，我这边图上立刻跟着变。**

```python
# 第 1 阶段：三车去同一个区域集结
write_goals({"UGV1": (1100, -400), "UGV2": (1200, -400), "UGV3": (1300, -400)})
time.sleep(30)

# 第 2 阶段：发现敌人后改派去打
write_goals({"UGV1": (1535, -889), "UGV2": (1727, -741), "UGV3": (1985, -626)})
```

### 4.5 另一种方式：直接用 Python API（不用文件）

如果你和我在**同一个进程**里（见第 2 节的现象 B），可以直接调：

```python
fleet.set_target("UGV1", 1200, -400)     # 单台
fleet.set_targets({...})                 # 批量
fleet.targets()                          # 看现在都有哪些目标
```

但**跨进程的话这个没用**（我读不到你的内存），必须写 `goals.json`。

> 💡 建议：**两个都做**——内部用 API，同时把同一份目标写进 `goals.json`。
> 这样图上星标和车实际去的地方永远是同一个，演示时不会出现"星标在这、车往那跑"。

## 5. 敌人"被发现"是怎么标记的（探测接口）

> 这一节给**负责无人机的同学**（葛伊诺）重点看。现在用的是**固定半径**判定，
> 实际探测模型你们可以改，改法见 5.3。

### 5.1 现在的判定逻辑：固定半径 + 坐标匹配

```
每 0.5 秒（--detect-every 10）
   │
   ├─ 让无人机节点调 SDK 的 detect_situation()
   │     └─ SDK 返回"探测半径内的所有 Actor"（半径由场景配置决定）
   │
   ├─ 拿返回的坐标，和 targets.json 里的已知目标逐个比距离
   │     ├─ 距离 < --detect-tol（默认 20 m）→ 认为是同一个 → 空心变实心
   │     └─ 都对不上                          → 画橙色叉（不在配置里的目标）
   │
   └─ HUD 左上角更新"已发现 N / M"
```

**半径不是我的脚本设的**，来自场景配置 `vehicles.json` 里每台平台的 `detectRadius`：

| 平台类型 | `detectRadius` 配置值 | 换算 |
|---|---|---|
| 无人机 `vehicle.hrt.m10` | `30000` | 若按厘米 = **300 m**；若按米 = 30 km（⚠️ 单位待实测确认） |
| 无人车 `vehicle.imv.rb` | `10000` | 若按厘米 = **100 m**；若按米 = 10 km |

> 想确认单位，跑一次 `python WorkPlace\missions\live_track.py --probe`，
> 看 `[3] 探测接口` 打印的 `Position=(X, Y)` 量级：和 `get_location()` 同量级就是米，
> 大 100 倍就是厘米。

所以**现在这个模型本质上是**：圆形范围、无遮挡、瞬时发现、不区分朝向。

### 5.2 探测相关参数（现在就能调）

| 参数 | 默认 | 作用 |
|---|---|---|
| `--detect-from` | `uav` | 用哪些平台探：`uav` / `ugv` / `all` |
| `--detect-every` | `10` | 每 N 帧探一次（20Hz 下约 0.5 秒） |
| `--detect-tol` | `20` | 探测结果与已知目标判定为"同一个"的距离阈值（米） |
| `--no-detect` | 关 | 完全不做 SDK 探测（敌人一直空心） |

### 5.3 想改探测模型怎么办（三档改造）

| 你想改什么 | 怎么做 | 要不要动我的代码 |
|---|---|---|
| **只改探测距离** | 改 `practice1_Scene/vehicles.json` 里的 `detectRadius`，改完**必须重启 `subject4.exe`** 才生效 | 不用 |
| **加视场角 / 建筑遮挡 / 发现延迟 / 概率** | 你的脚本自己算"发现了哪些目标"，写进 `config/detected.json`（见 5.4） | 不用 |
| **完全不用 SDK 的半径判定** | 启动加 `--no-detect`，只靠 `config/detected.json` | 不用 |
| **改判定阈值/数据源逻辑** | 告诉我，我改 `live_track.py` 里 `match_detections()` 那一段 | 找我改 |

> 关键原则：**我只负责"上色"，不关心你是怎么算出来的**。
> 你只要告诉我"哪些目标被发现了"，我这边就点亮它。

### 5.4 外部探测结果接口 `config/detected.json`

你的模型算出结果后，写进这个文件，**保存即生效**（我这边按修改时间热重载）：

```json
{
    "points":     [{"x": 1535.5, "y": -889.3}],
    "discovered": [8, 10],
    "extra":      [{"x": 900, "y": -700, "type": "dynamic.prop.soldier"}],
    "__清空__":   false
}
```

| 字段 | 含义 |
|---|---|
| `points` | 按**坐标**匹配已知目标（和 SDK 探测同一套逻辑）。**推荐用这个**，最直观 |
| `discovered` | 按**下标**直接点亮（0 开始）。适合你已经有一份"目标编号表"的情况 |
| `extra` | 不在 `targets.json` 里的目标，画成橙色叉 |
| `__清空__` | `true` = 把所有目标恢复成空心（重跑实验时用） |

`points` / `discovered` 写一个就够，两个都写就取并集。

#### 怎么知道某个目标的下标是几

两种办法：

**① 看运行日志**（最省事）：SDK 探测到新目标时会打印

```
[live_track] 发现目标 #8 路障（旁挂士兵）(1535.5, -889.3)
```

**② 打印完整编号表**：

```powershell
python -c "import sys; sys.path.insert(0,'WorkPlace'); from core import scenefile; [print(i, t.type, round(t.x,1), round(t.y,1)) for i,t in enumerate(scenefile.load_targets(r'Materials\practice\practice1_Scene\targets.json'))]"
```

> ⚠️ 编号顺序 = `targets.json` **展开后**的顺序，包含路障旁边挂着的士兵（`flowers`）。
> 所以重新生成敌人（`spawn_targets.py`）之后，编号会变，别写死。

#### 写文件的要求（和 goals.json 一样）

```python
import json, os, tempfile

DETECTED_PATH = r"<你的路径>\WorkPlace\config\detected.json"

def write_detected(points, extra=None, clear=False):
    data = {"points": [{"x": float(x), "y": float(y)} for x, y in points],
            "extra": extra or [],
            "__清空__": bool(clear)}
    d = os.path.dirname(DETECTED_PATH)
    fd, tmp = tempfile.mkstemp(dir=d, suffix=".json")
    with os.fdopen(fd, "w", encoding="utf-8") as f:
        json.dump(data, f, indent=4, ensure_ascii=False)
    os.replace(tmp, DETECTED_PATH)      # 原子替换，避免读到半截文件
```

### 5.5 三条一致性约定（很重要）

1. **用外部探测时，建议同时加 `--no-detect`。**
   否则 SDK 的半径判定和你的模型会**取并集**——你的模型还没判定发现，SDK 可能因为进半径先点亮了，
   图上就和你的算法对不上。
2. **`detectRadius` 改完一定要重启 `subject4.exe`。**
   `vehicles.json` 是场景进程启动时读的，改了不重启等于没改。
3. **别把"未发现"写成"已发现"。**
   `detected.json` 只表达"本次发现了什么"，不是"完整状态清单"。
   我这边是**只增不减**（除了 `__清空__`），所以写之前想清楚要不要先清空。

  * 世界 **x 越大 → 图上越靠右**

## 8. 写代码时的注意事项（踩坑清单）

### 8.1 别做的事

| ❌ 不要 | 为什么 |
|---|---|
| 自己画轨迹/位置 | 我这边自动画。你自己再画一份会重复、还会拖慢控制循环 |
| 用 `time.sleep` 长时间阻塞 | 控制循环会丢帧，车的动作会一顿一顿。要等就用状态判断 |
| 两个脚本同时控制同一台车 | 控制量会互相打架，车会抽搐 |
| 改 `Materials/` 里的文件 | 课程原始文件，改了别人对不上 |
| 改 `core/fleet.py` | 要改告诉我，统一改 |
| 在 `Materials/practice/easy_follow/` 目录里跑脚本 | `image_process.skeleton_refinement()` 会往当前目录写 **67 MB** 的 tga |
| 把目标点写到楼里/界外 | A\* 会失败；无人机可以飞，但车不行 |

### 8.2 要做的事

* **控制频率 ~20 Hz**（`time.sleep(0.05)`）。太快没意义，太慢车会顿。
* **每轮都读最新状态**再算（不要缓存上一帧的位姿）。
* **写日志到文件**，不要疯狂 print（刷屏会拖慢循环，也不方便排查）：
  ```python
  logf = open("run_%s.log" % time.strftime("%H%M%S"), "w", encoding="utf-8")
  ```
* 用 `try/finally` 确保**退出时停车**：
  ```python
  try:
      ... 主循环 ...
  finally:
      for v in fleet.vehicles("ugv"):
          v.apply_control(0, 0, 1.0, False)     # 刹车
  ```
* 每次实验前跑一次 `reset_scene.py`，保证从基准状态开始（否则上一轮的车还在原地跑）。

### 8.3 环境相关的坑

* **必须 Python 3.6 + swarmae**（SDK 的 egg 是 py3.6 专用）
* `global_planner.py` 需要 `cv2`；没有就 `pip install opencv-python==4.1.2.30`
* `np.mat` 在 NumPy 2.0 被删了，`Materials/` 里的库用了它 —— 在 py3.6/NumPy1.x 下没问题
* `get_road_network()` 会先请求竞赛服务器（你机器上肯定连不上），**失败后用本地内置图**，属正常
* 无人机高度基准：`subject4.exe` 里初始 z=10 或 100，起飞目标别设太低（建议 60 m 以上，避开建筑）
* ⚠️ **`SwarmAEClient(...)` 会解析你自己的 `sys.argv`**：它内部用 argparse，只认
  `-i/-p/-s/-n/-t`；所以脚本一带自定义参数，构造时就报
  `error: unrecognized arguments`。用 `core/sdk_boot.py` 的 `make_client()` 代替：

  ```python
  from core.sdk_boot import make_client
  client = make_client("127.0.0.1", 2000)   # 构造期间保护 argv，完成即还原
  ```

```python
# -*- coding: utf-8 -*-
"""control_xxx.py —— 我的移动控制逻辑（可直接跑，把标注处换成你的算法）"""
import json
import math
import os
import sys
import time

WORKPLACE = r"<改成你的路径>\WorkPlace"
EASY_FOLLOW = r"<改成你的路径>\Materials\practice\easy_follow"
sys.path.insert(0, EASY_FOLLOW)
sys.path.insert(0, WORKPLACE)

from swarmae.SwarmAEClient import SwarmAEClient
from core.fleet import Fleet

GOALS_PATH = os.path.join(WORKPLACE, "config", "goals.json")
DT = 0.05                      # 20 Hz


def read_goals():
    if not os.path.isfile(GOALS_PATH):
        return {}
    with open(GOALS_PATH, "r", encoding="utf-8") as f:
        data = json.load(f)
    out = {}
    for k, v in data.items():
        if k.startswith("__"):
            continue
        if isinstance(v, dict):
            out[k] = (float(v["x"]), float(v["y"]))
        elif isinstance(v, (list, tuple)) and len(v) >= 2:
            out[k] = (float(v[0]), float(v[1]))
    return out


def wrap_pi(a):
    while a > math.pi:
        a -= 2 * math.pi
    while a < -math.pi:
        a += 2 * math.pi
    return a


def main():
    client = SwarmAEClient(ue_ip="127.0.0.1", ue_port=2000)
    _, game, _ = client.get_game()          # 后面要 A* 时才用得到 game

    fleet = Fleet(client)                   # 注册 3 车 3 机
    goals = read_goals()
    print("目标:", goals)

    if goals:
        fleet.set_targets(goals)

    # 想用现成的 A* + Stanley/PID，补上 scene / img_skl 后调：
    #     fleet.plan(scene, img_skl, spacing=15)
    # 想自己写算法，就跳过 plan()，直接在下面的循环里 apply_control

    try:
        while True:
            snap = fleet.snapshot()

            for name, p in snap.items():
                g = goals.get(name)
                if g is None:
                    continue

                dx, dy = g[0] - p.x, g[1] - p.y
                dist = math.hypot(dx, dy)

                # ===================== 你的算法 =====================
                if name.startswith("UGV"):
                    # 无人车：闭环，给转向 + 油门/刹车
                    heading_err = wrap_pi(math.atan2(dy, dx) - p.yaw)
                    steer = max(-1.0, min(1.0, heading_err * 1.5))
                    # ⚠️ 实测若发现"转反了"，改成 steer = -steer
                    if dist > 12:
                        throttle, brake = 0.5, 0.0
                    else:
                        throttle, brake = 0.0, 1.0
                    fleet.vehicle(name).apply_control(steer, throttle, brake, False)
                else:
                    # 无人机：开环，只给目标点和地速
                    if dist > 8:
                        fleet.vehicle(name).target_point_control(
                            g[0], g[1], 60.0, 12.0)
                # ===================== 你的算法 =====================

            time.sleep(DT)

    except KeyboardInterrupt:
        pass
    finally:
        for v in fleet.vehicles("ugv"):
            try:
                v.apply_control(0, 0, 1.0, False)
            except Exception:
                pass
        print("已停车")


if __name__ == "__main__":
    main()
```
