# 无人机模块说明

本模块仅负责 `UAV1`、`UAV2`、`UAV3` 的起飞、搜索、侦测及结果输出。入口为同目录 `control_uav.py`，兼容 Python 3.6。模块被 import 时不会注册节点、连接仿真或下发指令。

## 1. 侦测与移动约定

- 主循环 `DT=0.05`，目标频率 20 Hz；每 10 帧依次调用三架无人机的底层 `detect_situation()`。SDK 延迟超过周期时记录超时，不进行密集补帧。
- 仅接受 `code == 200` 且 `Type` 为 `strike`、`enemy` 或 `hostile` 的对象。当前课程 SDK 的敌方可打击目标使用 `strike`；`teammate`、`obstacles`、`Other` 不作为敌方。不记录已明确死亡的对象。
- `Position.X/Y/Z` 固定除以 **100** 转为米，再校验目标与观测无人机的**水平距离不超过 300 m**。不使用三维球形距离，也不按坐标大小猜单位。
- 全局 `discovered_enemies` 保存真实目标的 `(x, y, z)` 米制代表坐标；按 **15 m 水平距离**合并重复观察，保留首次代表点，避免均值不断漂移。多个相距不足 15 m 的真实目标可能合并，这是本接口约定的分辨率。
- 起飞和全部巡航指令的目标高度固定为**世界坐标 Z=250.0 m**，巡航速度 **15.0 m/s**；起飞通过高度、水平位置连续 5 帧满足容差后才开始水平搜索。完成搜索或退出时仅向三架 UAV 尝试发送原地悬停指令，速度为 0。

依据为本地 `codex_outputs/live_detection_20261027/实测报告.md` 及原始记录：同高目标约 299 m 可检出、301 m 不可检出；接口厘米位置与 SDK 米制位置相差 100 倍；车辆高度对照中约 100～190 m 有漏检，约 250 m 恢复可见。因此本次按要求选用 Z=250 m。它不是经过所有建筑验证的离地安全高度，也不保证半径内的敌人一定可见。

## 2. 航线与禁飞区

从所选场景目录只读加载 `game.json` 和 `vehicles.json`。优先使用组长的 `Materials/practice/practice1_Scene/`；不存在时使用本机 `environment/subject_config/subject4/`。也可以用 `--scene` 明确指定，必须与当前运行的 `subject4.exe` 场景一致。

三机将东侧 `x∈[1200,2200]、y∈[-890,-60]` 等分为三个相邻子区，各自在 `y=-890、-390、-60` 三条搜索线上往返飞行；前两条相距 500 m，末条贴合搜索区边界，间距为 330 m。起点到搜索区的航段也持续侦测。一次扫描结束后悬停继续侦测，不自动返航或降落。

规划使用可见图和最短路自动插入绕行点：

1. 原始禁飞多边形先取外包矩形，再向外扩 30 m，保守覆盖其真实安全边界；不规则区域因此会多避让一部分空域。
2. 规划另留 10 m 跟踪余量，候选绕行角点再外移 5 m；到点容差为 3 m。
3. 任务边界向内留 10 m（与禁飞区的 30 m 边界分别处理），检查每一段航线；每轮还检查实际位置到当前目标点的连线。
4. 无安全路径、无效位置、实际位置越过安全边界或巡航高度偏差超过 5 m 时停止搜索，记录原因，并尝试仅对 UAV 原地悬停。不会退回直线硬飞。

当前解析器明确支持本项目的矩形 `arena` 和三处禁飞多边形。其他格式会拒绝启动。几何检查保证的是规划航段与下发目标；仿真惯性、遥测延迟及飞控故障仍需实飞验证，不能宣称实际飞机在任何故障下都绝不越界。当前未加入三机间的动态避碰。

本地 D4 范围为 `x∈[-1900.3,2277.4]、y∈[-1108.1,341.7]`。三处禁飞区的原始顶点依次为：

```text
1: [(-1011.3,-331.1), (-851.5,-331.1), (-851.5,-171.8), (-1011.3,-171.8)]
2: [(374.9,-631), (534.9,-631), (534.9,-471), (497.4,-471),
    (497.4,-380.7), (337.8,-380.7), (337.8,-539.4), (374.6,-539.4)]
3: [(1844.2,-322.7), (2005.1,-322.7), (2005.1,-270.2), (2109.8,-270.2),
    (2109.8,-110.6), (1950.3,-110.6), (1950.3,-161.7), (1845.2,-161.7)]
```

## 3. 运行方法

以下命令均在项目根目录运行。正常飞行需已安装课程 SDK 的 Python 3.6，并启动与所选配置一致的仿真、飞控驱动、场景程序。

先做离线航线预览，不连接仿真，也不修改共享配置：

```powershell
python WorkPlace/missions/control_uav.py --plan-only
```

航线输出到 `codex_outputs/uav_module/search_plan.json`。

正常侦测和飞行：

```powershell
python WorkPlace/missions/control_uav.py --scene environment/subject_config/subject4
```

组长三车三机场景就绪后：

```powershell
python WorkPlace/missions/control_uav.py --scene Materials/practice/practice1_Scene
```

默认输出测试，**不连接仿真、不飞行**：

```powershell
python WorkPlace/missions/control_uav.py --output-only --use-default
```

随实际飞行启用默认输出，首次真实发现后切换到真实坐标：

```powershell
python WorkPlace/missions/control_uav.py --use-default
```

`--use-default` 单独使用仍会起飞搜索；仅测试接口时必须加 `--output-only`。预设测试点为 `(1535.5,-889.3)、(1727.0,-741.0)、(1985.0,-626.0)`，不计入真实发现列表。

日志统一写入 `codex_outputs/uav_module/run_uav_%H%M%S.log`，不在终端持续打印。运行中按 Ctrl+C 退出并尝试仅对 UAV 悬停；不调用会制动无人车的 `Fleet.stop_all()`，也不自动重置场景。

### 节点编号与依赖

`Fleet` 的 UAV 编号固定为 4/5/6，而本机 D4 配置是七车三机，通常对应 8/9/10。本脚本使用一个很薄的 `UavVehicle` 适配器，提供相同形式的 `target_point_control(x,y,z,v)`，内部调用 SDK 已实测的 `control_kinetic_simply_global`。不构造默认 Fleet，不依赖当前缺失的 `Materials/.../lib/swarm_api.py`，也没有 UGV 控制分支。

默认按所选 `vehicles.json` 的平台顺序推导三个编号，支持 `--node-nos 8 9 10` 显式指定。**配置顺序不等于运行时对象映射的保证**：下发任何移动指令前，必须验证全部三个 SDK 实际 Actor 都是互不相同、存活的 `vehicle.hrt.m10`，否则拒绝飞行。这项验证依赖当前课程 SDK 的 `_SwarmAENode__actor` 句柄；SDK 版本不提供它时同样拒绝运行。不会把注册时传入的“无人机”名称当成真实类型证明。

## 4. 输出接口与协作

### A. Python 函数

在项目根目录可调用：

```python
from WorkPlace.missions.control_uav import get_detected_enemies

enemy_xy = get_detected_enemies()                 # [(x, y), ...]，单位米
test_xy = get_detected_enemies(use_default=True)  # 无真实目标时才回退到测试点
```

同进程共用模块实例时读取内存；其他进程调用时读取 `codex_outputs/uav_module/enemy_state.json` 的最后一次成功发布快照，因此无需再启动 UAV 控制器。该快照包含 `updated_at`、`synthetic`、`use_default`、`real_enemies`，便于核对来源与时间。控制器停止后它仍保留，**不是实时在线保证**。前次以 `--use-default` 发布的模式也会被跨进程读取；正常飞行成功启动后会重新初始化输出为本轮数据。

若没有真实数据且未开启默认模式，返回空列表。正常模式绝不把预设坐标写入 `discovered_enemies`。

### B. 可视化和无人车读取 detected.json

每次新增真实目标，或启动默认输出时，用 `tempfile.mkstemp` 加 `os.replace` 原子发布累计目标：

```json
{
  "points": [{"x": 1535.5, "y": -889.3}],
  "extra": [],
  "__清空__": false
}
```

路径为 `WorkPlace/config/detected.json`。无人车/任务分配模块可读取 `points` 中所有坐标，选择或分配多个目标；可视化端按坐标匹配点亮实心圈。建议显示端使用原有 `--no-detect` 参数，仅消费本模块输出，避免其他 SDK 探测源提前点亮目标。

默认点仅用于联调。显示端的发现标记只增不减，而本模块按约定始终发布 `__清空__: false`；默认测试结束后应重新开始显示会话，避免旧测试点残留。输出目标不代表无人机负责武器控制。

### C. 小地图目标星标

每架 UAV 起飞/切换航点时，读取 `WorkPlace/config/goals.json`，仅更新相应 `UAV1/2/3` 的 `[x,y]`，保留所有 UGV 目标、注释及其他字段，再用临时文件原子替换。原文件损坏时拒绝覆盖，不用空字典“修复”丢失队友内容。

原子替换防止读到半个 JSON，但无法让不协作的多进程读改写自动成为事务。若任务分配模块也同时写同一文件，组长应统一写入入口或采用双方共同遵守的锁，避免竞争覆盖。脚本不使用 `goals.json` 反向接收控制目标；它按本模块生成的安全航线飞行。
