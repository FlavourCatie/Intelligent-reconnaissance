## 一、当前整体效果（一句话结论）

**三辆 UGV 已能做到互不干扰地独立规划最优路径、独立绕障、独立驶向各自目标点**；但「三辆全部准时到达」还差最后一点，卡在两个**测试目标点选点不当**上（不是算法问题），详见第四节。

## 二、已达成的功能

1. **三车并行独立控制**
   每辆 UGV 一个独立 agent，独立目标点、独立路径、独立状态机，互不共享控制权。

2. **路网获取与解锁**
   通过 `get_road_network()` 拿到 1px 骨架路网（`skeletonized_image.png`），按顺序先跑完侦察阶段解锁（`reconnaissance_start → reconnaissance_end → vau_reconnaissance_start → vau_reconnaissance_end`），否则拿不到路网。

3. **A* 最短路径规划**
   在骨架路网上做 8 邻域 A*，world↔pixel 坐标变换（scale=1.0，固定 world_offset），得到从出生点到目标的最短路线。

4. **真车在线重规划（绕障）**
   边开边用 `detect_fun()` 探测（UGV 探测半径 100m）；一旦路障挡在剩余路径上：刹停 → 把路障按半径封进路网 → 从当前位置重跑 A* 得到绕行路径。

5. **死路倒车**
   若绕行路径开头要往回走（死路），先直线倒车退出路口（倒车 + 12m 越过量），再沿新路径前进。

6. **超车（本次新增，关键）**
   前方队友停死（连续 3s 静止、位移 <1m）→ 在真实路宽图（`roadnet_raw.png`，路宽约 17m）上测量垂直方向哪一侧更宽 → 向宽侧做 S 形侧偏（偏移 5m）越过挡路车 → 越过后回到中心线；若两侧都不够宽，则停车上报而不是无限等待。

7. **队友 / 无人机 / 路障 分类**
   `detect_fun()` 返回类型区分：`RaiderBuggy`=队友 UGV、`HRT-M10`=无人机（超车/刹车时排除）、`Other`=路障。

8. **横向 + 纵向控制**
   Stanley 横向跟踪 + PID 纵向调速；临近拐点减速（20m 内降到 2.5m/s，直道 5m/s）。

9. **兜底保护**
   超时（600s）、撞停（速度 <0.3 持续 8s）、无路可走、超车无空间 → 统一停车上报，不空转。

## 三、过程中调整过的问题

| # | 问题 | 处理 |
|---|---|---|
| 1 | **前方队友挡路 → 无限等待**（2 号车停在 1 号车前进路线上，1 号车一直刹车） | 加超车算法：3s 判定队友停死 → 侧向偏移超车 → 越过回中；无空间则停车上报。已修复。 |
| 2 | **路网获取有门槛**：刚启动直接取路网返回 FAIL | 必须先跑完侦察阶段（stage_start/complete 顺序），否则 `get_road_network()` 拒绝。已在入口处理。 |
| 3 | **无人机被误判为障碍/队友** | 超车与刹车判定中排除 `HRT-M10`。 |
| 4 | **目标点落在路外**，车冲过终点后越开越偏 | 到达判断改用「吸附到路网的最近点」（path 末尾），不再用原始目标点直接比距离。 |
| 5 | **路宽测量不能用 1px 骨架** | 骨架只有 1px 中心线，量不出垂直方向哪边宽；改用 `roadnet_raw.png`（真实填充路，约 17m 宽），且在直线段测量（路口会 over-count 扫到交叉路）。 |
| 6 | **路障没有精确类别/尺寸** | `detect_fun` 只返回 `Type=Other`，按固定半径 BLOCK_R=10 封盘处理。 |

## 四、未解决的小问题（已知，交付时说明即可）

1. **场景与路线图对不上（最重要）**
   UE 3D 场景里的道路/目标点与骨架路网图存在坐标系或边界偏差，表现是：
   - 目标点有时落在路网尽头之外或路外，导致车辆吸附后提前停车、或冲出路外；
   - 路障在路网图上的位置与 3D 场景可能有偏差。
   **待做**：核对 world_offset / scale 标定，或确认路网图来源（eval 接口 `get_road_network` 返回的图）与当前 UE 场景是否同一版本。

2. **UGV1 目标点 (-1000, -520) 在主路尽头之外**
   主路向东到约 x≈-1083 就断，目标在断点外，导致 UGV1 吸附到 -1030 提前 30m 停车。

3. **UGV3 目标点 (-1200, -870) 在北路障 (-1245, -870.9) 正后方**
   导致 UGV3 撞两次路障、两次倒车、绕行 2.5km+（直线仅 773m），最终超时。

4. **超车偏移是固定值（5m）**
   假设路面足够宽，未在极限窄路验证；窄路会走「无空间停车上报」分支。

5. **超时上限固定 600s**
   目标点较远 + 绕行较大时会超时（UGV3 就是例子）。

6. **与无人机联调尚未接入**
   目前目标点是在代码里写死的（`TARGETS`）。整体流程需要无人机侦察后把 2–3 个目标坐标传下来；UAV 航线格式（`submit_plane_route`）尚未解出。

## 六、正式比赛建议

1. 目标点尽量选在**路面范围内、且不在路障正后方**的地方，距离适中——即使绕路也不会超时。
2. 目标坐标建议由无人机侦察结果传入（当前是写死）。
3. 交付前先核对「场景 ↔ 路线图」标定，避免目标点/路障位置偏差。
